# 现场操作手册（草稿）

[English](demo-operator.md) | 中文

给在台上**亲手操作鸿蒙电脑**的人看的。照着做，演示就不容易翻车。
点击坐标、自动化脚本和彩排数据在 [demo.md](demo.md)（英文），这里只讲"手怎么动、眼睛看什么、嘴上说什么"。

> **草稿，还没在最终环境里完整彩排过。** 凡是标 **（待彩排确认）** 的地方，要在彩排时亲手走一遍再划掉。

## 先记住三条铁律

1. **同一时间只能开一台虚拟机。** 鸿融、OSEasy、Docker 后台虚拟机，三个里只能有一个在跑。第二台会被系统拒绝（401 "Not support vm multi-instance"）。所以每一段结束，**先把虚拟机关干净，再进下一段**。
2. **虚拟机一律从里面关机**：在 Omarchy 里按 **Super+Esc → Shutdown**。不要从鸿融点"关机"（它是灰的，正常），不要在虚拟机里"重启"，不要"注销"。
3. **原生桌面的窗口别关**，最小化就行。关掉"Omarchy (native)" 后再点图标，桌面约 6 秒会自己重新起来，但里面开着的窗口都没了。

"Super" 键就是键盘上的 Windows 徽标键。**在原生桌面（第 1 部分）里，按 Super 快捷键请用右 Alt 代替**：Windows 键会被鸿蒙拿去弹开始菜单，很多组合也被鸿蒙占用；app 会把右 Alt 当成 Super 发给 Omarchy。虚拟机里（第 2、3 部分）照常用 Windows 键。

## 演示顺序（约 10 分钟）

## 0. 演示前 1 分钟检查

能用眼睛看的都用眼睛看。要敲命令的标了 **【后台】**：由台下的助手在自己的电脑上（`ssh ohdev`）做，Yao 不用碰。

| # | 检查项 | 怎么确认 |
|---|---|---|
| 1 | 电源插着 | 右下角电池图标有充电标志 |
| 2 | 亮度调高、屏幕不会自动熄灭 | 设置里把自动熄屏改长或"永不"（具体菜单位置待彩排确认） |
| 3 | 免打扰打开 | 控制中心里有"免打扰"就打开（鸿蒙电脑上的具体开关位置待彩排确认） |
| 4 | 没有其他人/程序在操作这台电脑 | 【后台】通知所有远程会话、自动化脚本停手，演示期间谁也不要 ssh 去点屏幕 |
| 5 | **没有任何虚拟机在跑** | 看屏幕：鸿融打开后，虚拟机卡片的预览图**不是活的桌面**，"开机"按钮能点。注意：鸿融的卡片在虚拟机运行时**也**显示"已关机"，所以只看文字不算数。【后台】最终确认：`ssh ohdev pidof stratovirt` 什么都不输出 |
| 5b | **鸿融不会自己开机** | 鸿融"虚拟机 → 功能设置 → 启动与闲置"里"自动启动虚拟机"和"闲置自动暂停"都是关的（2026-10-26 发现它们开着：鸿融一被打开或拉起，虚拟机就自己开机，会占掉第 1 段 Docker 要用的 HMV）。开场前不要点 dock 上的鸿融。【后台】`ssh ohdev pidof stratovirt` 有输出，并且 `ps -ef \| grep stratovirt` 里是 com.huawei.medivh 的，就从鸿融界面关掉它：Omarchy 盘装了增强服务，用"关机"；主盘没装，用"更多 → 强制关机"。关完再确认 `pidof stratovirt` 为空 |
| 6 | 原生桌面已经在后台跑起来 | 开机就自动启动，不用管（2026-10-26 真重启验证过：开机约 50 秒后桌面已在后台，登录后双击图标直接出桌面）。【后台】`ssh ohdev sh /data/local/archtest/bin/omarchy desktop status`；没在跑就 `... omarchy desktop start`（约 3 秒） |
| 7 | 桌面干净 | 只留鸿蒙自己的桌面；鸿融、OSEasy、"Omarchy (native)" 都没开着窗口；清掉通知 |
| 8 | Dock 上能找到三个图标 | "Omarchy (native)"、鸿融（橙黄色图标）、OSEasy |
| 9 | 鸿融关了自动更新 | 应用市场曾经自己把鸿融换了版本。现在应是 1.1.1.103 |
| 10 | OSEasy 处在"已装好的虚拟机"状态 | 打开 OSEasy 能看到"再次安装"（**待彩排确认**：新流程正在改）。看完就关掉 OSEasy 窗口 |
| 11 | OSEasy 的试用还没过期 | OSEasy 每台设备只能试用一次（**待彩排确认**：看一下 app 里有没有到期提示） |
| 12 | 鸿融虚拟机的登录密码记在 Yao 脑子里 | 密码不写进任何文件，包括本手册 |
| 13 | 备用视频/截图已打开在另一台电脑上 | 见文末"备用方案" |

## 第 1 段：D 原生桌面 + I Docker（约 2 分钟）

| # | 手上做什么 | 屏幕上应该出现什么 | 等多久 | 嘴上说什么 |
|---|---|---|---|---|
| 1.1 | 在鸿蒙桌面上**双击** **"Omarchy (native)"** 图标（app 没开时 Dock 里没有它） | 先是一个写着"在等什么"的窗口，然后出现 Omarchy 壁纸和顶栏 | 约 10 秒 | "这不是虚拟机。Arch Linux 的程序直接跑在鸿蒙内核上，桌面画在一个普通的鸿蒙 app 窗口里。" |
| 1.2 | 点窗口标题栏上的**最大化** | 桌面铺满屏幕 | 1 秒 | |
| 1.3 | **Super+Return**，输入 `fastfetch` 回车 | 一个终端，fastfetch 显示 Arch Linux ARM、HongMeng 内核、Hyprland | 10 秒 | "看内核那一行：HongMeng，鸿蒙自己的内核。程序是 Arch 官方仓库里原样的二进制。"（GPU 那一行写的是 llvmpipe：那是终端自己用 CPU 画字，整个桌面的合成走的是 GPU） |
| 1.4 | **Super+2**，再 **Super+1**，来回几次 | 工作区左右滑动，很顺 | 10 秒 | "这是 120Hz，用马良 GPU 画的，实测 110～119 帧。" |
| 1.5 | **Super+Shift+B** | Firefox 在终端旁边打开（新窗口，不会再出"恢复会话"页）。可以打开 omarchy.org。第一次可能弹一个小提示，点 "Okay, Got It" | 15 秒 | "浏览器是 Firefox，带沙箱。" |
| 1.6 | **Super+Space** 弹出 Omarchy 菜单，看一眼，按 **Esc** | Omarchy 菜单出现又关掉 | 5 秒 | "这就是 Omarchy 原汁原味的菜单。" |
| 1.7 | **Super+Shift+F** | 文件管理器（Nautilus）打开主目录 | 5 秒 | |
| 1.8 | 点回终端，输入 `docker run --rm hello-world` 回车 | 先停一会儿（后台虚拟机在启动），然后出现 **"Hello from Docker!"** | **第一次约 15–20 秒**，别慌 | "鸿蒙内核跑不了容器，所以 Docker 自动借了一台很小的后台虚拟机，用的时候才开，用完半分钟自己关。我没敲任何 root 命令。" |
| 1.9 | **不用管**，Docker 虚拟机会自己关 | 没有可见变化 | 约 30 秒，讲 1.8 的说辞时就过去了 | "用完它自己就关了，下一段的虚拟机马上能开。" |
| 1.10 | 把"Omarchy (native)" **最小化**（不要关） | 回到鸿蒙桌面 | 2 秒 | |

**1.9 Docker 虚拟机自己关**（2026-10-26 彩排：hello-world 冷启动 21 秒，跑完后什么都不碰，约 35 秒 `pidof stratovirt` 为空）：没有容器在跑、也没有 docker 连着，就在 30 秒后自动关机。**这期间别再敲 `docker` 命令**，每敲一次都会重新计时。万一没关，见下面故障表最后一行。

说明：2026-10-26 在 ohdev 上彩排过（按键经鸿蒙的输入服务注入，右 Alt 当 Super）：1.1–1.7 全部和表里一样，双击图标后约 10 秒出桌面。第 1 部分里所有的 "Super" 都按**右 Alt**；按 Windows 键会弹出鸿蒙的开始菜单（点回桌面就关掉）。

### 第 1 段：出了状况怎么办

| 现象 | 怎么办 |
|---|---|
| 点了图标，窗口一直写着"在等…"，桌面不出来 | 原生桌面没在后台跑（开机自启没生效；正常不会发生，刚开机不到 1 分钟时可能还没起来）。【后台】`omarchy desktop start`，等 10 秒。还不行：关掉 app 窗口，【后台】`omarchy desktop stop; omarchy desktop start`，再点图标。台上说一句"我们换个顺序"，直接跳到第 2 段鸿融 |
| 不小心把"Omarchy (native)" 关了 | 再双击一次图标：桌面会自己重新启动，约 6 秒（2026-10-26 彩排过，不用任何后台命令）。之前开着的窗口会没了，重新打开就行（Super = 右 Alt） |
| 按 Super+Return 等快捷键没反应，或者弹出鸿蒙开始菜单 | 用**右 Alt** 代替 Windows 键。先用鼠标点一下 Omarchy 窗口里面，让它拿到焦点再按。还不行：跳过快捷键，只展示已经打开的东西 |
| 某个窗口卡住不动 | 用 **Super+W** 关掉这个窗口，继续下一步 |
| `docker` 停了 15–20 秒没输出 | 正常，第一次要开后台虚拟机。边等边讲 |
| `docker` 报：`后台 Docker 虚拟机启动不了：鸿融或者 OSEasy 的虚拟机正在运行，请先关掉它` | 有别的虚拟机在跑（违反了检查项 5）。台上：说"这正是一次只能跑一台虚拟机的限制"，跳过 Docker。【后台】看是哪台；进下一段鸿融前要先关掉它 |
| `docker` 超过 1 分钟还没输出 | 按 Ctrl+C，跳过 Docker，放备用截图（`docs/img/autostart/03-docker-cold.jpeg`）。【后台】`ohmarchy-vm stop`，确认 `pidof stratovirt` 为空再进第 2 段 |
| hello-world 之后过了 1 分钟，鸿融开机提示有别的虚拟机在跑 | Docker 虚拟机还没关（比如中间又敲过 `docker`）。在终端敲 `docker-vm stop`（约 6 秒，提示"Docker 虚拟机已关闭"）；如果它说还有容器在跑，先 `docker ps`、`docker stop <名字>`。或者【后台】`ohmarchy-vm stop` |

## 第 3 段：B OSEasy（约 3 分钟）

开始前确认：鸿融虚拟机已经关好（2.9）。

> 这一段的流程**正在改**：以前每次都要从 ISO 重新装（约 3 分钟），现在改成"再次安装"直接从已经装好的硬盘启动。下面按新流程写，**整段待彩排确认**。

| # | 手上做什么 | 屏幕上应该出现什么 | 等多久 | 嘴上说什么 |
|---|---|---|---|---|
| 3.1 | Dock 上点 **OSEasy** | OSEasy 主界面，有"再次安装"（待彩排确认） | 2 秒 | "OSEasy 是第三方的 Windows 虚拟机 app，本来只给 Windows 用。" |
| 3.2 | 点 **再次安装** | 可能先出现"正在安装 Windows 11…"窗口：**正常**，它以为装的是 Windows。然后虚拟机控制台出现，前面盖着介绍轮播，点 **收起介绍** | 几秒 | "它界面上写的是 Windows 11，实际里面是 Omarchy。" |
| 3.3 | 等 | Omarchy 的 Hyprland 桌面（应该是自动登录，待彩排确认） | **约 10 秒**（待彩排确认；旧流程实测重启后 6 秒进桌面） | "这里的显卡是我们自己改的 Linux 驱动，让 Linux 用上了 OSEasy 给 Windows 准备的 3D 加速。" |
| 3.4 | **Super+Return** 开终端，输入 `es2gears_wayland` 回车 | 转动的齿轮 | 10 秒 | "虚拟机里每秒画 120 帧，屏幕上 60 帧，因为 OSEasy 不向系统要高刷新率。" |
| 3.5 | **Super+2**、**Super+1** 来回几次 | 切换顺滑 | 10 秒 | "带着 GPU 负载连续跑了 4 个多小时没出错。" |
| 3.6 | 回到齿轮窗口按 **Super+W** 关掉（之后开 app 才快） | 齿轮消失 | 2 秒 | |
| 3.7 | **Super+Return** 再开一个终端（foot） | 几乎瞬间出现（实测 0.08 秒） | 1 秒 | "开终端 0.08 秒。" |
| 3.8 | 在终端里输入 `chromium` 回车（或 Super+Shift+B，待彩排确认是不是 Chromium） | Chromium 窗口出现（实测 0.8 秒） | 2 秒 | |
| 3.9 | 关机：**Super+Esc → Shutdown** | 虚拟机关掉；OSEasy 回到它的界面（具体显示什么，待彩排确认） | 约 20 秒 | |

**OSEasy 关机后千万别点"取消"**：在"安装失败"那类对话框里，"取消"会**删掉这台虚拟机**，下次就得从 ISO 重新装（约 3 分钟，还要后台推磁盘）。只点"再次安装"，或者什么都不点直接关 OSEasy 窗口。

## 问答小抄

**Q：A 到 L 这么多路线是什么？为什么只演示 D、I、C、B？**
A：A 是鸿蒙自带 Linux 容器里的命令行工具，没有桌面；E 裸机没开始；F 只在 Mac 上的模拟器里、纯软件很慢；G 铠大师和 H 真机上的 Aetherium 确认走不通；J（把 Linux 程序签进 app，不要 root）现在只跑到 busybox；K 没开始；L 浏览器内核里跑 Linux 暂停了。能拿出来演示的就是 D、I、C、B。

**Q：可以归纳一下吗？**
A：两条线。**线一：在虚拟机 app 里即插即用**（B、C），不要 root，今天就能用，差的是 app 自己（60Hz、OSEasy 按 Windows 设计、鸿融要增强服务）。**线二：原生**（D + I），效果最好（120Hz、直接用 GPU、78 个 app 有 74 个 3 秒内打开），但要 root。

**Q：为什么虚拟机里只有 60Hz？**
A：鸿蒙只在某个窗口主动"要"120Hz 时才把屏幕调到 120Hz。鸿融和 OSEasy 都不要。虚拟机里其实在按 120Hz 画（鸿融里 119.98Hz，OSEasy 每秒 120 帧送到宿主），是 app 显示时只给 60Hz。原生桌面的 app 会主动要 120Hz，所以是 119 帧。

**Q：D 为什么要 root？**
A：要用 chroot 和挂载把 Arch 环境搭起来，还要一个 root 小程序把 GPU 连接转给 app。普通 app 不能运行没签进安装包的程序（XPM 代码完整性保护），也拿不到需要的内核功能。

**Q：鸿蒙要提供什么，才能不用 root 跑原生？**
A：四件事：
1. **允许 app 运行自带的 Linux 程序**（为这种情况放宽 XPM，或者给一种专门的签名/权限）；
2. **内核功能**：user namespace、cgroup v2、进程间共享 `CLONE_FS`（沙箱、容器、Chromium 沙箱都要）；
3. **开放虚拟机接口**（现在是写死的 8 个 app 白名单，Docker 后台虚拟机要用）；
4. **修 HMV 的 ID 寄存器问题**（新内核读不认识的 ID 寄存器会把 vCPU 卡死；我们写了报告给华为）。

有了前两项，D 就能不用 root、以现在的性能跑。

**Q：原生桌面上的 Docker 是怎么回事？**
A：鸿蒙内核没有容器需要的命名空间和 cgroup，所以 Docker 跑在一台我们自己起的、没有界面的小虚拟机里：root 直接在 `/dev/hmv`（鸿蒙的虚拟化层）上启动系统自带的 StratoVirt。**不是鸿融**，也**不是鸿蒙自带的融合开发引擎**（那个是容器，跑不了 Docker）。第一次敲 `docker` 时它自己开机（约 20 秒），用完 30 秒自己关，个人目录共享进去，挂载目录照常能用。空闲时只占宿主约 1.2 GB 内存。

**Q：为什么一次只能开一台虚拟机？**
A：鸿蒙的虚拟化层系统级只允许一台，第二台直接被拒（401 "Not support vm multi-instance"）。所以演示是一段一段交接的。

**Q：鸿融为什么显示"已关机"？**
A：鸿融要等虚拟机里它的"增强服务"报到才显示运行中。我们的系统里还没装它（正在做），所以从里面关机。

**Q：普通用户能用上吗？**
A：线一（B、C）不要 root，对外发布正在准备：镜像放 GitHub Releases，加上写给普通用户的说明。
