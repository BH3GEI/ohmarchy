虚拟机方式（B、C）

系统虚拟机服务的访问控制

  • 调用方需要 ohos.permission.MANAGE_VM（system_basic，system_grant）。
  • libvm_manager.z.so 内写死 8 个 appIdentifier，包括 OSEasy（com.oseasy1.ohvm）和铠大师（com.sanway.ecoengine）。
  • 调试签名的第三方应用调用时返回 201，被拒绝。详见 vm-api.md。
  • 系统同一时间只允许一台虚拟机，第二台返回 401 "Not support vm multi-instance"。

原生方式（D、I、J）

D 原生桌面

  • Arch Linux ARM 用户态以 chroot 方式运行于 HongMeng 内核，需要 root 权限。
  • Hyprland 以无头模式渲染，经 dmabuf 交由鸿蒙应用 com.ohmarchy.display 显示。
  • GPU 链路：virgl → vtest → 系统 libvirglrenderer → zink → 马良 GPU。
  • Chromium testufo：修复前 60–73 fps，修复后 118 fps（e5416df）。
  • 已修复：触控板滚动、三指切换工作区、按键粘滞。
  • Super 键被鸿蒙开始菜单占用，右 Alt 映射为 Super（f6ab403）。
  • pacman 使用清华 TUNA 源。
  • 支持开机自启（f39ce23）；关闭应用后重新打开，约 6 秒恢复桌面。

I 自建虚拟机

  • 以 root 权限直接打开 /dev/hmv，使用系统自带 StratoVirt 启动。
  • 作为 D 的 Docker 后端：首次使用时启动，空闲 30 秒后自动关闭（5687442）。
  • 与鸿融、OSEasy 的虚拟机互斥。

J app 沙箱原生

  • 真机实测：普通应用无法获得可写可执行内存，无法 exec 未签名 ELF，也无法 dlopen 未签名 .so；签入 HAP 的 .so 可以加载。
  • Hyprland 0.56.2 及依赖用鸿蒙 musl 编译为 libhyprland.so，签入 com.ohmarchy.display 应用。
  • 已解决的卡点：dma_heap 权限、vtest 句柄。

B 公开试用版

  • 镜像不含预设密码，首次开机时在 tty1 设置；安装无需联网。
  • 安装盘目标 < 2 GiB（GitHub 单个附件上限 2 GiB；鸿蒙文件管理器无法解压分卷 zip）。
  • GitHub 草稿 release 附 GPL 源码包；缺少源码的包列于 release notes 首行，补齐后方可公开。
  • 许可：MIT；内核及驱动相关代码 GPL-2.0。
